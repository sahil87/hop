# CLI Subcommands

What each subcommand of the `hop` binary actually does. Source files live in `src/cmd/hop/`.

The grammar is **`hop <selection> <action>`, selection-first** (change `gyo0` — grammar + shim refactor). The shell shim no longer hard-codes the subcommand list. Instead it forwards the user's argv to the binary's hidden `--shim-plan` classifier, which emits a fixed 3-keyword protocol the shim interprets — see [Shim ↔ binary `--shim-plan` protocol](#shim--binary---shim-plan-protocol) below and [architecture/wrapper-boundaries](../architecture/wrapper-boundaries.md).

`<selection>` is a repo name (substring → fzf on ambiguity), a `repo/worktree`, a group name, or `--all` (every cloned repo). `<action>` is a builtin verb (`cd`, `open`, `where`), a batch verb (`pull`/`push`/`sync`), any PATH binary (`git pull`, `code .`), or a shell alias/function (`p`). Omit the action to cd into the selection.

When `$1` is a registered cobra subcommand (`add`, `rm`, `clone`, `ls`, `shell-init`, `config`, `update`), normal cobra dispatch applies (the classifier emits `PASSTHROUGH`). `pull`/`push`/`sync` are **action tokens, not subcommands** — they appear only after a selection (`hop <selection> pull`). When `$1` is a selection, the binary's root `RunE` (`runRoot` in `root.go`) — reached directly via `PASSTHROUGH` or by scripts bypassing the shim — switches on `len(args)` and `args[1]`: 0 args → bare picker (print path); 1 arg → group-with-no-action (plural usage error) or bare-name cd hint (shell-only); 2 args, `args[1] == "where"` → resolve and print; 2 args, `args[1] == "cd"` → cd-verb hint (shell-only); 2 args, `args[1] == "open"` → delegate to `wt open`; 2 args, `args[1]` ∈ {`pull`,`push`,`sync`} → batch verb over the selection; 2 args, anything else → tool-form hint (shim-only). The root command uses `cobra.ArbitraryArgs` (no positional cap) because tool-form action tokens carry their own argv. The verbs `cd`, `where`, and `open` are NOT subcommands at `$1` — they exist only at `$2` after a selection.

**Worktree-aware grammar extension** (change `7eab`): the `$1` selection positional accepts an optional `/<wt-name>` suffix — `hop <name>/<wt-name>` — that resolves to the absolute path of the named worktree. The split happens inside `resolveByName` (see [match-resolution](match-resolution.md)) and is invisible to cobra. Every form that runs through `resolveByName` inherits the suffix for free: bare `hop <name>/<wt>` (shim cd via the `CD` plan), `hop <name>/<wt> where`, `hop <name>/<wt> open`, and the shim's tool-form `hop <name>/<wt> <tool> [args...]` (via the `RUN_IN_PARENT` plan). The `/` is safe as a separator because `hop.yaml` repo names are URL basenames (single component, no `/`) — see [config/yaml-schema](../config/yaml-schema.md). Worktree resolution shells out to `wt list --json` (a second wrapped wt call alongside `wt open` — see [architecture/wrapper-boundaries](../architecture/wrapper-boundaries.md)).

Match resolution algorithm used by the `--shim-plan` classifier (for `CD`/`RUN_IN_PARENT` path resolution), `hop` (bare picker), `hop <name> where`, `hop clone`, and `hop rm <name>` is documented separately in [match-resolution](match-resolution.md). The name-or-group resolver used by the `pull`/`push`/`sync` batch verbs (which adds an exact group-match step in front of the substring repo match, plus an `--all` step) is described in the same file under [Name-or-Group Resolution](match-resolution.md#name-or-group-resolution).

## Migration: hidden config aliases

The registry-edit verbs `add` and `rm` live at the **top level** (`hop add <dir>`, `hop rm [<name>]`) as their canonical home, sitting alongside the other top-level subcommands (`clone`, `ls`, `shell-init`, `config`, `update`). (`pull`/`push`/`sync` are no longer subcommands — they are action tokens after a selection, see change `gyo0`.) `hop config add` / `hop config rm` are retained as **hidden aliases** (`Hidden: true` cobra commands) so existing scripts and muscle memory keep working with **zero breakage**.

How the canonical/alias pair is wired (no logic duplication):

- **Shared `RunE` bodies, per-path prefix**: `config_add.go::runAdd(cmd, cmdName, userArg)` and `config_rm.go::runRm(cmd, cmdName, stale, name)` are the single bodies behind both spellings. The command-name prefix is a **string parameter** threaded into every stderr line (and into `addSkipMessage(cmdName, …)` / `pickRepo(cmdName, …)`), not a module-level constant — the old `addCmdName` / `rmCmdName` consts were removed. The canonical factories pass `"hop add"` / `"hop rm"`; the hidden alias factories pass `"hop config add"` / `"hop config rm"`. So a bad-dir error reads `hop add: '<dir>' is not a directory.` via the top-level command and `hop config add: '<dir>' is not a directory.` via the alias — historically-accurate per path.
- **Factories**: `newAddCmd()` / `newRmCmd()` (top-level, wired in `root.go::newRootCmd().AddCommand(...)`) and `newConfigAddCmd()` / `newConfigRmCmd()` (`Hidden: true`, wired under `config` in `config.go::newConfigCmd().AddCommand(...)`). All four live in `config_add.go` / `config_rm.go` — no new files.
- **Positional asymmetry**: the new `hop rm <name>` positional path (`cobra.MaximumNArgs(1)`) is **exclusive to the canonical top-level `hop rm`**. The hidden `config rm` alias keeps `cobra.NoArgs` (picker-only) — it passes an empty `name` to `runRm`, so it can never take the positional path.
- **`config` parent summary**: `newConfigCmd()`'s `Short` is `"config helpers (init, where, print)"` — `add` / `rm` are dropped from the one-liner since `config` is no longer their documented home (it stays a namespace for *meta* operations on the config file: `init`, `where`, `print`). `scan` was also dropped when the `config scan` subcommand was deleted (change `260608-w2bj-unify-recursive-add` — see [`config scan` is deleted, no alias](#config-scan-is-deleted-no-alias) below).
- **`config` parent RunE (unknown-command guard)**: `newConfigCmd()` uses `Args: cobra.ArbitraryArgs` with a `RunE` that branches on `len(args)`: zero args → `cmd.Help()` (bare `hop config` prints help); non-empty args → `fmt.Errorf("unknown command %q for %q", args[0], cmd.CommandPath())`. Cobra only routes a leftover positional to the parent's RunE when no child command matches, so valid subcommands (`init`/`where`/`print` and the hidden `add`/`rm` aliases) still dispatch to their own RunE first. This is what makes the deleted `hop config scan` surface as `unknown command "scan" for "hop config"` (change `260608-w2bj-unify-recursive-add`).
- **Help-surface filtering**: being `Hidden`, the aliases are absent from `hop --help` and `hop config --help`, and self-filter out of `hop help-dump` JSON via `shouldSkipChild`'s `Hidden` drop (the same mechanism that hides `help-dump` itself) — so the published `help/hop.json` reference lists `add`/`rm` at the top level and omits the `config add`/`config rm` aliases. The `rootLong` Usage table (`root.go`) carries `hop add <dir>` and `hop rm [<name>]` rows.
- **Completion collision**: `repo_completion.go`'s dynamically-built `subNames` filter (sourced from `cmd.Commands()`) picks up `add`/`rm` automatically — a repo literally named `add` or `rm` is dropped from bare-name `$1` completion (a selection named `add` would be shadowed by the cobra subcommand at `$1`; reach it via `hop add where`). No code change there.

### `config scan` is deleted, no alias

Unlike `add`/`rm` — which moved to the top level but kept **hidden `config` aliases** for zero-breakage backward compatibility — `hop config scan` was **deleted outright with NO alias** (change `260608-w2bj-unify-recursive-add`). Its recursion folded onto `hop add -r` (with print/write inverted to `-p`-opt-in; see the `hop add <dir>` inventory row and [config/add-register](../config/add-register.md)). `newConfigScanCmd()`, `runConfigScan`, and `scanLong` are gone from `config_scan.go` / `config.go`; the file's shared helpers (`validateConfigDir`, `buildScanPlan`, `slugifyGroupName`, conflict/invented helpers, `scanPlanSummary`) remain because `add` depends on them. `hop config scan <anything>` now returns cobra's `unknown command "scan" for "hop config"` (a deliberate hard break — the user rejected both a hidden alias and a deprecation notice). The mechanism is the `config` parent's unknown-command `RunE` (see the **`config` parent RunE** bullet above). Migration: `hop config scan <dir> --write` → `hop add -r <dir>`; `hop config scan <dir>` (old print default) → `hop add -r -p <dir>`.

## Migration: auto-init-on-write

Change `260605-44hm-auto-init-on-write` widened the three **write-commands** (`hop add`, the recursive `hop add -r` — formerly `hop config scan --write`, change `260608-w2bj-unify-recursive-add` — and `hop clone <url>`) to **auto-create** a missing `hop.yaml` (minimal `repos: {}` skeleton, announced `created: <path>`) instead of erroring with the old require-`config init`-first gate. The substance of the auto-init set is unchanged from the original change — only the recursive-add command *spelling* moved from `config scan --write` to `hop add -r`. Implications for callers:

- The missing-config **exit-1** path on these write-commands is **gone** — replaced by create-then-proceed. (`$HOME`-unset still exits 1 for `add`; `clone` propagates it.) Note `hop add -p` (print-mode dry-run, any breadth) is NOT a write-command — it never auto-inits and errors on a missing config.
- **Read-commands are unchanged** — `hop`, `hop ls`, `hop <name> where`, `hop config print`, and `hop add -p` print-mode dry-runs still error on a missing config (now via the refined `Resolve()` message that points at both `hop add` and `hop config init`).
- **`hop rm` / `hop config rm` is NOT auto-init** — it keeps its own historical gate (`Run 'hop config init' first, then re-run rm.`, `config_rm.go`), since `rm` has nothing to register on a fresh machine. This leaves `rm`'s wording slightly diverged from the refined `Resolve()` message — a known, deliberate carve-out (a follow-up cleanup candidate, not a regression).
- **Breaking-ish**: scripts that relied on these write-commands *failing* when no config exists (e.g. a guard) now succeed and create the file. Low risk — failing-on-absence was never a documented contract.

See [config/init-bootstrap § Auto-init-on-write](../config/init-bootstrap.md#auto-init-on-write-change-260605-44hm-auto-init-on-write) for the full design.

## Removed subcommands

The `path` subcommand has been removed (no alias). Use `hop <name> where` or the bare form `hop <name>` (shim only).

The top-level `where` and `cd` subcommands were removed in the v0.x repo-verb grammar flip (no aliases). Use `hop <name> where` and `hop <name> cd` (or the bare `hop <name>` shorthand for the shim's `cd`). The verb position migrated from $1 (subcommand) to $2 (verb following a repo). `hop config where` survives unchanged (different namespace).

The `config path` subcommand has been removed (no alias). Use `hop config where`.

The `code` subcommand has been removed (no alias). Use the tool-form: `hop <name> code` (if `code` is on PATH) — the `--shim-plan` classifier returns `RUN_IN_PARENT\n<path>` and the shim runs `cd -- <path>; shift; code`.

The `pull`, `push`, and `sync` **subcommands** were removed in change `gyo0` (grammar + shim refactor). They are now **action tokens** after a selection: `hop pull <name>` → `hop <name> pull`; `hop pull --all` → `hop --all pull`; `hop pull <group>` → `hop <group> pull`. The `-m`/`--message` flag that the `sync` subcommand exposed is also gone — `sync` uses the fixed `chore: sync via hop` message.

The `-R` flag and its silent shim rewrite were removed in change `gyo0`. Tool-form (`hop <name> <tool> ...`) is now the native grammar, handled by the `--shim-plan` classifier's `RUN_IN_PARENT` plan — there is no `-R` flag, no `extractDashR`/`runDashR` in `main.go`, and no `hop: -R: '<cmd>' not found` error. Migration: `hop -R <name> <cmd>` and `hop <name> -R <cmd>` → `hop <name> <cmd>`.

The `open` subcommand was removed in v0.x (along with the `internal/platform` cross-platform abstraction) and later **reinstated as a $2 verb** in `hop <name> open`. The new verb does not own platform abstraction itself — it shells out to `wt open`, which handles app detection, menu selection, and launching for editors, terminals, file managers, multiplexer tabs, and the "Open here" cd path. See the inventory row above. The Darwin one-liner for "open repo dir in Finder" is preserved by selecting "Finder" from wt's menu (one extra keystroke vs. the old tool-form). On Linux, the new verb gives a working menu UX where the prior tool-form `hop <name> xdg-open` was the only option.

## Ad-hoc URL clone

`hop clone <url>` (URL form, detected by `looksLikeURL`: contains `://` OR (`@` AND `:`)) clones a URL not in `hop.yaml`, then registers it.

Flow:
0. **Auto-init** (change `260605-44hm-auto-init-on-write`): `config.ResolveWriteTarget()` + `config.EnsureSkeleton(path)` — creates the minimal `repos: {}` skeleton when absent (announces `created: <path>` to stderr). When `EnsureSkeleton` returns `created==true`, also call `yamled.EnsureGroup(path, group)` to create the target group (`<group>: []`) before step 1 — a fresh skeleton has no groups, so without this the default/`--group` target wouldn't exist. `EnsureGroup` runs **only** on a freshly-created file, so a typo'd `--group` against a pre-existing config still falls through to step 1's `findGroup==nil` error (preserving `AppendURL`'s `ErrGroupNotFound` typo-catching contract). See [config/init-bootstrap § hop clone ensure-group](../config/init-bootstrap.md#hop-clone-url-ensure-group-step).
1. Resolve target group (`--group <name>`, default `default`). Missing group **in a pre-existing config** → exit 1 with `hop: no '<group>' group in <config-path>. ...` (on a freshly auto-created config the group was just ensured in step 0, so this can't fire).
2. Compute landing path. For map-shaped groups (`dir:` set): `<dir>/<name>`. For flat groups: `<code_root>/<org>/<name>` (org dropped if URL has none). `--name` overrides the URL-derived name.
3. Classify on-disk state:
   - `stateMissing` → `git clone <url> <path>`, then append URL to `hop.yaml` (unless `--no-add`), print path on stdout (unless `--no-cd`).
   - `stateAlreadyCloned` → emit `skip: already cloned at <path>` to stderr; still appends YAML and prints path (registers existing checkout).
   - `statePathExistsNotGit` → emit `hop clone: <path> exists but is not a git repo`; exit 1; no YAML write, no stdout.
4. URL already in target group's `urls` list → emit `skip: <url> already registered in '<group>'` to stderr, no YAML write, but still print path (unless `--no-cd`).

YAML write goes through `internal/yamled.AppendURL` (comment-preserving, atomic temp+rename — see [architecture/package-layout](../architecture/package-layout.md#internalyamled)).

## Exit code convention

Defined in `main.go::translateExit`:

| Code | Trigger |
|---|---|
| 0 | Success |
| 1 | Application error (default for all unmatched errors); also `errSilent` (caller already wrote stderr) |
| 2 | `errExitCode{code: 2}` — used by the `cd` verb, `shell-init`, `hop add`/`hop config add` (bad dir), `hop rm` (`--stale` combined with a positional name), the tool-form binary hint, and the plural-selection guard (`--all`/group with a non-batch action) for usage errors |
| 130 | `errFzfCancelled` — fzf user cancellation (Esc / Ctrl-C) |

Cobra's `SilenceUsage: true` and `SilenceErrors: true` are set on `rootCmd`, so `translateExit` is the sole stderr/exit path for top-level errors.

The hidden `--shim-plan` flag is handled **before** cobra parses argv (in `main.go::main()` via `extractShimPlan`); `runShimPlan` writes its plan/stderr and `main` calls `os.Exit(runShimPlan(...))` directly. Its `shimResolveErr` helper mirrors `translateExit`'s code policy (fzf-missing → 1, fzf-cancel → 130, `errExitCode` → its code), so the classifier path returns the same exit codes as every other binary entry point.

## Shared helpers (`where.go`)

- `loadRepos() (repos.Repos, error)` — `config.Resolve()` → `config.Load()` → `repos.FromConfig()`. Used by every subcommand that reads `hop.yaml`.
- `resolveByName(query string) (*repos.Repo, error)` — implements the match-or-fzf algorithm without writing to stderr; returns typed sentinels (`errFzfMissing`, `errFzfCancelled`) so callers control which stderr to write to. **Pre-step (change `7eab`)**: if `query` contains a `/`, the function splits on the FIRST `/` (repo names from `hop.yaml` are URL basenames with no `/`, so first-`/` split is unambiguous even when wt worktree names themselves contain `/`), validates that both halves are non-empty (empty LHS / RHS returns an `*errExitCode{code: 2, msg: ...}`), recurses on the LHS to resolve the repo, then calls `resolveWorktreePath` to invoke `wt list --json` in the resolved repo's main checkout and find the entry whose `Name == rhs` (exact, case-sensitive). The returned `*repos.Repo` is a shallow copy of the LHS-resolved repo with `Path` replaced by the worktree's absolute path; all other fields (`Name`, `Group`, `URL`, `Dir`) describe the registry entry and stay unchanged. Worktree-resolution errors (uncloned-with-`/`, wt missing, no-such-worktree, malformed JSON) surface as `*errExitCode{code: 1, msg: <pre-formatted stderr line>}` so `translateExit` prints them verbatim — see "External tool failure messages" below.
- `resolveWorktreePath(repo *repos.Repo, wtName string) (*repos.Repo, error)` — sub-step of `resolveByName` for the `/`-suffixed branch (change `7eab`, lives in `resolve.go`). Guards: (1) repo MUST be cloned (`cloneState(repo.Path) == stateAlreadyCloned`) — this guard applies ONLY to `/`-suffixed queries so bare `hop <name> where` against uncloned repos keeps its existing permissive behavior; (2) invokes `listWorktrees(ctx, repo.Path)` (the package-level seam in `wt_list.go`); (3) returns the matching entry's path or one of the four `errExitCode` lines. Helper kept inline in `cmd/hop/` (NOT promoted to `internal/wt/`) per the wrapper-boundaries "promote later" pattern.
- `resolveOne(cmd, query) (*repos.Repo, error)` — cobra-friendly wrapper that writes `fzfMissingHint` to `cmd.ErrOrStderr()` and returns `errSilent` on missing fzf.
- `resolveAndPrint(cmd, query) error` — wraps `resolveOne` and writes `repo.Path` to stdout.
- `buildPickerLines(rs) []string` — builds the tab-separated lines piped to fzf. When two repos share a `Name`, the displayed first column gets a `[<group>]` suffix. The path column (used for match-back) is unique per repo. Reused by `hop rm`'s `pickRepo` (config_rm.go), which pipes the lines through the `pickOne` seam and maps the selection back to its `Repo` by the same unique path column.
- `validateConfigDir(userArg, cmdName, stderr) (canonical string, ok bool)` — shared dir-argument validator in `config_scan.go` (extracted in the `config add` rework, A-018). Applies `filepath.Abs → filepath.EvalSymlinks → os.Stat (is-dir)`; on any failure emits `<cmdName>: '<userArg>' is not a directory.` and returns `ok=false` so the caller exits 2. Now called solely by `runAdd` (`cmdName` is the per-path `"hop add"` / `"hop config add"` for the canonical add command and its hidden alias) — the former `config scan` caller was deleted (change `260608-w2bj-unify-recursive-add`). It originally replaced the previously-duplicated `validateScanDir`/`validateAddDir`. **Returns an absolute path** — change `260605-c92v-fix-relative-dir-args` swapped the leading `filepath.Clean` for `filepath.Abs` so a bare **relative** argument (e.g. `hop add fab-kit` from its parent dir) is resolved against the CWD before symlink evaluation; without it `EvalSymlinks` kept a relative input relative, leaving `Found.Path` relative and breaking downstream group derivation / convention matching (`filepath.Dir("fab-kit") == "."`). Absolute-arg behavior is unchanged.
- `pickRepo(cmdName, rs) (*repos.Repo, error)` + the package-level `var pickOne = fzf.Pick` seam (both in `config_rm.go`, change `260602-n1me-config-add-rm-folders`) — `pickRepo` builds the picker lines, runs `pickOne(ctx, lines, "")` (single-select), then maps the selected line back to its `Repo` by splitting on tab and matching the unique path column (`parts[1]`), the same approach `resolveByName` uses. `cmdName` is the per-path stderr prefix used in its error wording (`"hop rm"` / `"hop config rm"`). The `pickOne` seam mirrors the `listWorktrees` / `runInteractive` seam idiom: tests inject a fake selection to exercise the map-back + `RemoveURL` integration without spawning a real `fzf` (`resolve.go` calls `fzf.Pick` directly with no cmd-level seam, so its fzf path is unit-untestable — `config rm` deliberately added the seam to be testable). `pickRepo` maps `proc.ErrNotFound` → `errFzfMissing` and fzf exit-130 → `errFzfCancelled`. The positional `hop rm <name>` path never calls `pickRepo` — it resolves via `resolveOne`.
- `removeRepo(stderr, cmdName, configPath, repo) error` (in `config_rm.go`) — the shared tail of `runRm` used by **both** the picker path and the positional `<name>` path so they speak the same stderr voice. Calls `yamled.RemoveURL(configPath, repo.Group, repo.URL)`; the forgiving not-found case (`ErrURLNotFound` / `ErrGroupNotFound`) reports `<cmdName>: <url> not found in <path>. Nothing to remove.` and returns nil (exit 0); a real write failure returns `errSilent`; success emits `removed: <url>` + `wrote: <path>`.
- `listWorktrees(ctx, repoPath) ([]WtEntry, error)` — package-level `var` seam in `wt_list.go` initialised to `defaultListWorktrees`. The default builds a 5-second `context.WithTimeout` and routes through `proc.RunCapture(ctx, repoPath, "wt", "list", "--json")`, then unmarshals into `[]WtEntry`. The seam pattern mirrors `internal/fzf/fzf.go::runInteractive` — tests inject fakes without spawning a real `wt`. Three distinct features and four call sites: `resolveWorktreePath` (single-worktree lookup for `<repo>/<wt>` path resolution — change `7eab`), `ls.go::runLsTrees` (fan-out for `hop ls --trees` — change `7eab`), and tab completion in `repo_completion.go` (both the post-slash `completeWorktreeCandidates` from change `7eab` and the root-only pre-slash eager branch in `completeRepoNames` from change `odle` — the eager branch is gated to `cmd.Parent() == nil` so non-root subcommands like `hop clone <prefix>` retain their bare-repo-name behavior). Returns `proc.ErrNotFound` when `wt` is missing on PATH (callers match via `errors.Is` to produce the install hint). Still below the threshold for a dedicated `internal/wt/` package — all four needs are the same single-shot `wt list --json` with a 5-second timeout; see [architecture/wrapper-boundaries](../architecture/wrapper-boundaries.md) for the promote-later rationale.

The user-visible behavior is identical (single hint line on stderr, exit 1) — the indirection exists so `internal/update` stays free of cobra-specific sentinels.

## Binary-form hint texts (constants in `root.go`)

The root command's `RunE` returns one of three exit-code-2 errExitCode constants depending on the args shape (`bareNameHint`, `cdHint`, `toolFormHintFmt` — all in `root.go` next to `rootLong`).

`bareNameHint` (1-arg form `hop <name>`):

```
hop: bare-name dispatch is shell-only. Add 'eval "$(hop shell-init zsh)"' to your zshrc, or use: hop "<name>" where
```

`cdHint` (2-arg `cd` verb form `hop <name> cd`):

```
hop: 'cd' is shell-only. Add 'eval "$(hop shell-init zsh)"' to your zshrc, or use: cd "$(hop "<name>" where)"
```

`toolFormHintFmt` (2-arg tool-form `hop <name> <tool>` — `%s` gets `action`):

```
hop: '%s' is not a hop verb (cd, where, open, pull, push, sync). Tool-form runs in your shell — install the shim: eval "$(hop shell-init zsh)"
```

Tool-form runs in the parent shell (via the shim's `RUN_IN_PARENT` plan), so the binary can't honor it directly — the hint points at the shim. The `-R` migration path is gone (change `gyo0`): the hint no longer mentions `hop -R`.

The plural-selection guard (`runPluralSelection` in `root.go`, mirroring `shim_plan.go::classifyPlural`) emits two more exit-2 messages: `hop: '<sel>' is a plural selection — it needs a batch action (pull, push, sync).` (no action) and `hop: '<sel> <verb>' refused — '<verb>' is not a batch action. Plural selections accept only pull, push, or sync.` (non-batch action). `hop <group> where` / `hop --all where` are refused with `hop: '<sel> where' is not supported — 'where' resolves a single path. Use 'hop ls' to list every repo.`

The `where`-verb, `open`-verb, and batch-verb branches do not have a singular hint — they succeed and either print to stdout (where), exec wt with stdio inherited (open), or run the batch machinery (pull/push/sync).

When the user invokes `hop <name> open` directly (without the shim) and picks "Open here", the binary itself cannot mutate the parent shell; wt's own `wt shell-setup` hint surfaces from wt directly in that path, since the shim is the only caller that sets `WT_CD_FILE`. Hop intentionally does not own this hint — the cd-handoff is a shim concern, not a binary concern.

## `hop shell-init <shell>` emitted text

The shared portion (`shell_init.go::posixInit`) is identical for zsh and bash — both shells understand `[[ ]]`, `case`, `local`, and `printf '%s' | sed`. Only the appended completion script differs.

The shim is a **logic-free interpreter of the binary's `--shim-plan` protocol** (change `gyo0`). It hard-codes **zero** subcommand names — the subcommand list lives only in cobra, so shim/binary name-drift (the root cause of hop's "stale shim" bug class) is structurally impossible. See [Shim ↔ binary `--shim-plan` protocol](#shim--binary---shim-plan-protocol) below for the full classification contract.

The shared `posixInit` defines:

- `hop()` function — a 2-branch interpreter:
  1. **`$1` is `__complete*`** → `command hop "$@"` and return. Cobra's hidden completion entrypoints must reach the binary directly; routing them through `--shim-plan` would classify the completion request instead of answering it. This is the **only** token the shim special-cases by name (and it is a cobra-internal protocol token, not a subcommand name).
  2. **otherwise** → `plan="$(command hop --shim-plan "$@")" || return $?`, then `case` on the first line over exactly the 3 protocol keywords:
     - **`CD`** → `cd -- "$(printf '%s' "$plan" | sed -n 2p)"` (the plan's second line is the resolved path). Covers bare `hop <name>` and `hop <name> cd`.
     - **`RUN_IN_PARENT`** → `cd -- "<path>" || return $?; shift; "$@"` — cd into the resolved path, drop the selection token, and run the user's **already-parsed words** (`git pull`, `code .`, an alias `p`, etc.) in the parent shell.
     - **`PASSTHROUGH`** → `_hop_passthrough "$@"` (the binary owns it: `add`/`rm`/`clone`/`ls`/`config`/`update`/`shell-init`/`where`/`open`/`pull`/`push`/`sync`/`--help`/`--version`/...).
     - **`*` (default)** → `command hop "$@"`. Defensive graceful-degradation arm: an unrecognized plan (e.g. a future protocol keyword reaching an older shim) falls back to the binary so cobra prints a normal error. This is what makes a version handshake unnecessary (change `gyo0`, intake §10).

  **Security (Constitution I)**: the shim runs the user's already-parsed `"$@"` — **never** `eval` of binary output. The binary emits only the fixed vocabulary plus a path used solely as a quoted `cd` operand, so there is no re-parsing of binary stdout as code and no shell-injection surface.

- `_hop_passthrough()` helper — runs the binary while providing a **unified cd side-channel**. It `mktemp`s a temp file, points `WT_CD_FILE` at it (prefix-style on the `command hop "$@"` invocation), runs the command, then `cd -- "$target"` if the file is non-empty and the command exited 0; cleans up via `rm -f`. This **collapses the former three path-handoffs** (`where`=stdout, `open`=`WT_CD_FILE`, `clone`=conditional-stdout) into ONE channel (change `gyo0`, intake §4): `wt open`'s "Open here" and `hop clone <url>` write their cd-target to `WT_CD_FILE`; `where` still prints to stdout for scripts (no cd, the file stays empty); commands that resolve no cd-target (`ls`, `config`, ...) leave the file empty and no cd occurs. It does NOT capture stdout via `$(...)` — that would swallow wt's interactive menu and block on stdin. If `mktemp` fails it degrades to a plain `command hop "$@"`. Note `WT_WRAPPER` is **no longer** exported by the shim — the env-orchestration narrowed to just `WT_CD_FILE`.
- `h() { hop "$@"; }` — single-letter alias.

The `hi()` alias was **removed** (change `gyo0`) — `command hop` is the raw escape hatch (Constitution VI, minimal surface).

The cobra-generated completion is appended at runtime — `rootCmd.GenZshCompletion(out)` for zsh, `rootCmd.GenBashCompletionV2(out, true)` for bash. The `rootCmd` reference is captured in `main.go::rootForCompletion` (a package-level var set in `main()`). After the cobra completion, the shell-init emits the alias-completion line:
- zsh: `compdef _hop h`
- bash: `complete -o default -F __start_hop h`

so the `h` alias shares the same completion logic — without this, tab completion would only work on `hop`, not on `h`.

### Repo positional tab completion (`$1`)

The `ValidArgsFunction` for the root command's `$1` slot is `src/cmd/hop/repo_completion.go::completeRepoNames`. It runs three branches in order:

1. **Action position (`len(args) == 1` on the root command)** → return `["cd", "where", "open", "pull", "push", "sync"]` with `ShellCompDirectiveNoFileComp` — the builtin verbs plus the reoriented batch verbs (change `gyo0`). `pull`/`push`/`sync` complete here at `$2` (after a selection), NOT at `$1`, because they are action tokens, not subcommands. Non-root callers (e.g., `clone` via `completeCloneArg`) suppress completion past `$1`.
2. **Post-slash worktree branch (`toComplete` contains `/`)** → delegate to `completeWorktreeCandidates`, which splits on the first `/`, resolves the LHS via `rs.MatchOne`, invokes `listWorktrees(ctx, repo.Path)`, and returns `<lhs>/<wt>` strings (the full token the user is composing — cobra prefix-matches against `toComplete`, so bare wt names would mis-replace the LHS). Unchanged since change `7eab`.
3. **Pre-slash eager worktree branch (`toComplete` has no `/`)** — change `odle`. After collecting today's `names` slice (loaded repos minus the subcommand-collision filter), the function probes for an eager-expansion fire. All four guards must hold for the menu to surface:
   - `rs.MatchOne(toComplete)` returns exactly one repo. Ambiguous prefixes (0 or 2+ matches) bypass the branch entirely — the unique-match guard is the cost gate that prevents `wt list --json` fan-out across N repos. Empty `toComplete` falls into this case naturally because `MatchOne("")` returns every repo.
   - The matched repo's `Name` is NOT in `subNames` (subcommand collision). The collision filter runs BEFORE the eager check, so a repo literally named `clone` (which cobra would dispatch to the `hop clone` subcommand before the bare-form resolver ever sees it) is never offered with worktree suffixes.
   - `cloneState(repo.Path)` returns `stateAlreadyCloned`. Uncloned repos have no `.git` to query — matches `completeWorktreeCandidates`'s precedent.
   - `listWorktrees(context.Background(), repo.Path)` returns nil error AND `len(entries) >= 2`. The `>= 2` threshold means the menu only surfaces when worktree-vs-main is a real choice; a 1-worktree repo keeps today's auto-space-and-finalize behavior.

   When all four hold, the function returns `[<repo>, <repo>/<entries[0].Name>, <repo>/<entries[1].Name>, ...]` (bare repo at position 0, then `wt list --json` source order verbatim — matches `hop ls --trees` ordering, no alphabetical reordering) with directive `cobra.ShellCompDirectiveNoFileComp | cobra.ShellCompDirectiveNoSpace`. `NoSpace` is essential — without it the shell auto-finalizes `$1` after the user picks the bare form, defeating the menu. The bitwise-OR composes cleanly with the existing `NoFileComp` flag.

   **Silent-fallback contract**: every failure mode (uncloned, `wt` missing, `wt list --json` non-zero exit, malformed JSON, context timeout, fewer than 2 entries) returns the original `names` list with today's `ShellCompDirectiveNoFileComp` only. The completion path never writes to stderr — enforced by the package-level comment block in `repo_completion.go` and consistent with `completeWorktreeCandidates`.

   **Shell-degradation note**: bash users (and zsh users without `menu select`) see the eager candidates as a flat list rather than arrow-key navigation. Candidates are still surfaced; further disambiguation is by typing more characters. The bare-cd cost — `h <name><TAB>` against a multi-worktree repo no longer auto-spaces, so the user pays one extra Space keystroke to commit "use main" — is the accepted price of discoverability.

   No caching across Tab presses: each eager-fire invocation runs `wt list --json` fresh (Constitution II — no database; measured 6.3-8.1ms median latency is below the perception threshold). The shared `listWorktrees` seam is documented in [match-resolution](match-resolution.md#worktree-resolution-sub-step-change-7eab).

## Shim ↔ binary `--shim-plan` protocol

The dispatch contract between the shell shim and the binary (change `gyo0`). The shim asks the binary to classify the user's argv (`command hop --shim-plan "$@"`); the binary emits one of three fixed keywords; the shim acts on it. **The shim hard-codes zero subcommand names** — the subcommand list lives only in cobra (`isKnownSubcommand` walks `root.Commands()` live), so shim/binary name-drift is structurally impossible. This is the permanent fix for the "stale shim" bug class (an already-open shell running an out-of-date hard-coded subcommand `case`).

Classification lives in `shim_plan.go::runShimPlan` (first match wins):

| Input (`$@`) | Plan | Notes |
|---|---|---|
| no args | `CD\n<path>` | bare `hop` — fzf-pick a repo and cd into it (`emitCD("")`) |
| `$1` is `__complete*` | `PASSTHROUGH` | defense-in-depth; the shim already forwards `__complete*` directly |
| `$1` is a known cobra subcommand (`add`/`rm`/`clone`/`ls`/`shell-init`/`config`/`update`/`help`/`completion`) | `PASSTHROUGH` | `isKnownSubcommand` (live `root.Commands()` walk + aliases) |
| `$1` is a flag other than `--all` (`-*`) | `PASSTHROUGH` | `--help`, `--version`, etc. reach cobra |
| `$1 == --all` | plural selection (action = `$2..`) | `classifyPlural` — only `pull`/`push`/`sync` allowed |
| `$1` is an exact configured group name | plural selection | `isConfiguredGroupName` (case-sensitive, mirrors `resolveTargets` rule 2) |
| singular `$1`, no action | `CD\n<path>` | bare `hop <name>` |
| singular `$1`, `$2 == cd` | `CD\n<path>` | explicit cd verb |
| singular `$1`, `$2` ∈ {`where`,`open`,`pull`,`push`,`sync`} | `PASSTHROUGH` | binary owns these (path-print, wt menu, batch machinery) |
| singular `$1`, any other `$2` (tool-form) | `RUN_IN_PARENT\n<path>` | `git pull`, `code .`, an alias `p`, etc. run in the parent shell |

**Plural-selection guard** (`classifyPlural`, mirrored by `root.go::runPluralSelection` for the direct-binary path): a plural selection (`--all` or a group) accepts **only** the batch verbs. A plural selection with no action, or with `where`/`open`/`cd`/a tool, is a **usage error (exit 2)** — running an interactive action across N repos is nonsensical, and a plural selection has no single directory to cd into. Batch verbs on a plural selection emit `PASSTHROUGH` (the binary's `runBatchVerb` fans out).

The shim never `eval`s binary output (Constitution I): `CD`/`RUN_IN_PARENT` carry only a path used as a quoted `cd` operand, and `RUN_IN_PARENT` runs the user's already-parsed `"$@"`, not binary-generated code.

## Tool-form dispatch

Tool-form (`hop <name> <tool> [args...]`) generalizes the removed `hop code`/`hop open`/`-R` forms to any PATH binary, alias, or shell function. The selection lives in `$1` and the action in `$2..` — never the other way around. The `--shim-plan` classifier returns `RUN_IN_PARENT\n<path>` for a singular selection with a non-builtin action token; the shim runs `cd -- <path>; shift; "$@"`:

| User types | Plan from `--shim-plan` | Shim runs |
|---|---|---|
| `hop dotfiles cursor` | `RUN_IN_PARENT\n<dotfiles>` | `cd -- <dotfiles>; cursor` (in the parent shell) |
| `hop webapp git status` | `RUN_IN_PARENT\n<webapp>` | `cd -- <webapp>; git status` |
| `hop webapp code .` | `RUN_IN_PARENT\n<webapp>` | `cd -- <webapp>; code .` |
| `hop webapp p` (shell alias/function) | `RUN_IN_PARENT\n<webapp>` | `cd -- <webapp>; p` — aliases/functions resolve because the shim runs the user's literal words, not a binary exec |
| `hop webapp notarealbinary` | `RUN_IN_PARENT\n<webapp>` | `cd -- <webapp>; notarealbinary` → the **shell's** `command not found` (hop no longer owns this error) |
| `hop webapp where` | `PASSTHROUGH` | `command hop webapp where` — prints the path to stdout |
| `hop webapp cd` | `CD\n<webapp>` | `cd -- <webapp>` (no binary action call) |
| `hop webapp open` | `PASSTHROUGH` | `_hop_passthrough webapp open` — `command hop` execs `wt open`; "Open here" writes `WT_CD_FILE` and the shim cd's the parent |
| `hop webapp pull` | `PASSTHROUGH` | `_hop_passthrough webapp pull` — binary runs `git pull` in webapp and emits a `pull:` line |
| `hop webapp` (bare) | `CD\n<webapp>` | `cd -- <webapp>` (shorthand for `hop webapp cd`) |
| `hop where webapp` (legacy) | `RUN_IN_PARENT\n<where-repo>` if `where` matches a repo, else a resolution error | migrate to `hop webapp where` |

Tool-form is **shim-only**: the binary cannot mutate the parent shell. Direct binary invocations (`/path/to/hop dotfiles cursor`) hit `runRoot`'s default branch and print `fmt.Sprintf(toolFormHintFmt, "cursor")` (exit 2). Scripts and CI that bypass the shim use `hop <name> where` for path resolution and run tools themselves.

## `hop clone` per-line output

All status lines go to **stderr** (stdout is reserved for resolved paths, used by the shell shim's `cd`). Formats:

- `clone: <url> → <path>` (before invoking `git clone`)
- `skip: already cloned at <path>` (when `<path>/.git` exists)
- `skip: <url> already registered in '<group>'` (URL form, when URL is already in the target group's `urls` list)
- `hop clone: <path> exists but is not a git repo` (path conflict, exits 1 single / counts toward `failed` for `--all`)
- `summary: cloned=<N> skipped=<M> failed=<F>` (only `--all`)

Clone uses a 10-minute timeout (`clone.go::cloneTimeout`).

## `pull` / `push` / `sync` per-line output

All status lines go to **stderr** (stdout is empty — the shim does NOT `cd` after these verbs). Formats:

- `pull: <name> ✓ <last-line>` / `push: <name> ✓ <last-line>` / `sync: <name> ✓ <pull-summary> <push-summary>` (success — `<last-line>` is the last non-empty line of git's stdout via `lastNonEmptyLine` in `pull.go`; for pull e.g. "Already up to date." / "Fast-forward"; for push e.g. "Everything up-to-date" / "<src> -> <dst>")
- `sync: <name> ✓ committed, <pull-summary>, <push-summary>` (sync success when the auto-commit fired — comma-separated, `committed` prefix signals hop made a commit on the user's behalf; absence of `committed` in the line means the tree was clean and behavior matched the pre-auto-commit `hop sync`)
- `pull: <name> ✗ <err>` / `push: <name> ✗ <err>` / `sync: <name> ✗ <err>` (failure — git's own stderr is forwarded verbatim by `proc.RunCapture`; the hop line summarizes for the per-repo log)
- `sync: <name> ✗ commit failed: <err>` (auto-commit failed — typically a `pre-commit` / `commit-msg` hook rejection; rebase and push are NOT invoked when this fires. Mirrors the `push failed: <err>` shape)
- `sync: <name> ✗ rebase conflict — resolve manually with: git -C <path> rebase --continue` (specialized hop-side hint emitted only when git's output contains a `CONFLICT` substring on rebase failure; replaces the verbatim git error line for that case — `git push` is NOT invoked when this fires; applies to both clean and dirty paths)
- `sync: <name> ✗ push failed: <err>` (rebase succeeded but push failed — non-fast-forward, network, etc.; applies to both clean and dirty paths)
- `skip: <name> not cloned` (`<path>/.git` missing — counts toward `skipped` in batch mode; exits 1 in single-repo mode; shared verbatim across pull, push, and sync)
- `summary: pulled=<N> skipped=<M> failed=<K>` for `pull` / `summary: pushed=<N> skipped=<M> failed=<K>` for `push` / `summary: synced=<N> skipped=<M> failed=<K>` for `sync` (only batch mode — group match or `--all`)

Each git invocation runs through `internal/proc.RunCapture` with an **independent** 10-minute timeout (reusing `clone.go::cloneTimeout`), not a shared batch budget. `pull` and `push` use one context per repo (one git invocation each); `sync` uses up to five independent contexts per repo — `git status --porcelain`, then (only when status is non-empty) `git add --all` and `git commit -m <msg>`, then `git pull --rebase`, and finally `git push`. `git` missing on PATH emits `gitMissingHint` (`hop: git is not installed.`) once and aborts a batch immediately (no further repos attempted, no summary line emitted) — mirrors `clone.go::cloneAll`'s `proc.ErrNotFound` early-return.

## Sync auto-commit

`hop sync` auto-commits dirty working trees before the existing rebase + push. The motivation is to fully replace ad-hoc shell helpers (e.g., `xpush`-style scripts) with a single hop verb driven by `hop.yaml` rather than a hardcoded directory list. Behavior is default-on for dirty trees; clean trees are unchanged.

Per-repo order of operations (single repo `<path>`):

1. `git -C <path> status --porcelain` — dirty detection.
2. If status output is non-empty:
   1. `git -C <path> add --all` — stages tracked modifications, deletions, AND untracked files (matches xpush's `git add --all :/`).
   2. `git -C <path> commit -m "<message>"` — default message `chore: sync via hop`, overridable via `-m / --message <msg>` (string flag, no toggle — `-m` only changes the message; auto-commit remains on for dirty trees).
3. `git -C <path> pull --rebase` (existing).
4. `git -C <path> push` (existing).

Any step's failure aborts that repo's sync and counts toward `failed` in batch mode. Rebase and push behavior (including the `CONFLICT` substring detection and the `rebase conflict` hint) is identical to the pre-auto-commit code path.

**Hooks are respected.** No `--no-verify` is passed. A failing `pre-commit` (or `commit-msg`) hook causes `git commit` to fail, hop emits `sync: <name> ✗ commit failed: <err>`, and rebase + push are skipped. Users who want to bypass hooks can drop to the tool-form `hop <name> git commit --no-verify` (or run git directly).

**Fixed default message**: `chore: sync via hop` (the `defaultSyncCommitMessage` constant in `sync.go`). Chosen for Conventional Commits compatibility (`chore:` prefix), greppability (`git log --grep "via hop"`), brevity (19 chars), and honesty (commits are explicitly attributed to hop).

**No `-m`/`--message` flag** (change `gyo0`): the reoriented `sync` action token dropped the message-override flag the old `hop sync` subcommand carried. `runBatchVerb` always calls `syncOne(cmd, r, defaultSyncCommitMessage)`. A custom message goes through `hop <name> git commit` (tool-form) before `hop <name> push`.

**`hop push` is intentionally NOT changed** — see the inventory row above. The asymmetry exists because pushing without rebasing is the riskier op; `hop sync` is the safe verb because it always rebases first.

Helper: `commitDirtyTree` lives inline in `sync.go` (not extracted to a shared file). It encapsulates the `status → add → commit` sequence above, distinguishes a clean tree from a real failure, and emits the `sync: <name> ✗ commit failed: <detail>` line on its own so callers don't duplicate it. If a future subcommand needs the same shape, extract then.

## `hop update` — self-update via Homebrew

Implementation in `internal/update`; the cobra factory in `cmd/hop/update.go` is a thin wrapper. The flow:

1. **Detect brew install**: walk `os.Executable()` through `filepath.EvalSymlinks` and check whether the resolved path contains `/Cellar/`. If not, print `hop v<X> was not installed via Homebrew.\nUpdate manually, or reinstall with: brew install sahil87/tap/hop` and exit 0.
2. **Refresh brew index**: `brew update --quiet` with a 30-second timeout (via `proc.Run` + `context.WithTimeout`). Failure exits 1. This step is gated by `if !skipBrewUpdate` — passing `--skip-brew-update` skips it silently (the only step the flag affects). Steps 3–5 (info check, up-to-date short-circuit, upgrade) always run regardless of the flag.
3. **Query latest version**: `brew info --json=v2 sahil87/tap/hop` and parse `formulae[0].versions.stable`. The formula name is **fully qualified** (`sahil87/tap/hop`) to dodge a name collision with the Homebrew core `hop` cask (an HWP document viewer).
4. **Compare versions**: normalize both sides by stripping a leading `v` (binary reports `v0.0.3`, brew reports `0.0.3`). If equal, print `Already up to date (v<X>).` and exit 0.
5. **Upgrade**: `brew upgrade sahil87/tap/hop` with a 120-second timeout. Stream brew's stdout/stderr through to the user via `proc.RunForeground` so progress is visible. On success, print `Updated to v<new>.` and exit 0.

All `brew` invocations route through `internal/proc` (Constitution Principle I — no direct `os/exec` outside `internal/proc`). The package exposes `Run(currentVersion string, skipBrewUpdate bool, out, errOut io.Writer) error` as its single public entry point; `skipBrewUpdate` gates only the step-2 tap-metadata refresh (threaded from the `--skip-brew-update` flag in `cmd/hop/update.go`). The `out`/`errOut` writers receive only the wrapper messages this package emits; subprocess output from `brew` is routed by `internal/proc` to the parent's `os.Stdout`/`os.Stderr` directly. Production callers pass `os.Stdout` and `os.Stderr` (via `cmd.OutOrStdout()` / `cmd.ErrOrStderr()`) to keep both consistent. When `brew` is missing on PATH, `Run` returns `proc.ErrNotFound`; the cobra wrapper converts that to `errSilent` so `translateExit` doesn't print a second error line.

## `hop help-dump` — JSON help-tree contract

Implementation in `help_dump.go` (change `jr5f`); the factory `newHelpDumpCmd()` is wired into `newRootCmd()`'s `AddCommand(...)` alongside the user-facing subcommands. It is a **hidden** command (`Hidden: true`, `Args: cobra.NoArgs`) so it ships in the released binary — collectors can invoke it — without appearing in `hop --help`. It exists solely to feed the shll.ai landing site's "Command reference" UI. As of the 2026-06-03 transport inversion (change `g56l`), shll.ai **pulls** this artifact: its scheduled job installs hop and runs the binary's `hop help-dump`, collecting the output as `help/hop.json` (see [build/release-pipeline](../build/release-pipeline.md) § Help reference). hop no longer pushes the artifact downstream. This is hop's slice of a 7-tool rollout that all publish the same JSON shape (the reference is `wt`'s `help/wt.json`).

**Output contract** (frozen — mirrors `help/wt.json`):

```
Doc  = { tool, version, captured_at, schema_version: 1, root: Node }   // keys in this order
Node = { name, path, short, usage, text, commands: Node[] }            // commands = [] for leaves, never null
```

- `tool` is the literal `"hop"`; `schema_version` is the int constant `helpDumpSchemaVersion = 1`.
- `version` is read from the **live** `rootCmd.Version` (i.e. `main.version`, ldflag-injected — `"dev"` in an unstamped local build), **never hardcoded**. `RunE` calls `buildHelpDoc(cmd.Root())` so it sees the same wired root that has `Version` set and all subcommands attached.
- `captured_at` is left as the empty string `""` by the producer — it does NOT call `time.Now()`, keeping the dump deterministic and unit-testable. The collector (shll.ai's scheduled pull job) injects the timestamp when it gathers the artifact; the producer never stamps it.
- The document marshals via `json.MarshalIndent(doc, "", "  ")` (2-space indent) with a trailing newline, written to `cmd.OutOrStdout()`.

**Node fields** come from structured cobra accessors (NOT regex-parsing `-h` output): `name = cmd.Name()`, `path = cmd.CommandPath()`, `short = cmd.Short`, `usage = cmd.UseLine()`. The `text` field is built **uniformly** by `nodeText`: `cmd.Long + "\n\n" + cmd.UsageString()` when `cmd.Long != ""`, else `cmd.UsageString()` alone — so the root node's `text` carries the full `rootLong` narrative followed by the usage block, and the selection-first grammar (the `--shim-plan` dispatch, tool-form, batch verbs — documented in `rootLong` but not separate cobra nodes; `pull`/`push`/`sync` are action tokens and `--shim-plan` is handled pre-cobra) is *described* in the dump even though those are not separate nodes.

**Child filtering** (`shouldSkipChild`) drops, during the recursive walk: any child named `"completion"` or `"help"` (cobra auto-generated), any child with `Hidden == true` (which drops `help-dump` itself — the self-filter — plus the hidden `config add` / `config rm` aliases), and any `IsAdditionalHelpTopicCommand()` (defensive). So `root.commands` contains the **seven** user-facing top-level subcommands (`add`, `rm`, `clone`, `ls`, `shell-init`, `config`, `update`) and excludes `completion`, `help`, and `help-dump`. (`pull`/`push`/`sync` are no longer subcommands — they are action tokens and never appeared as cobra nodes after change `gyo0`.) The `Hidden` drop also self-filters the `config add` / `config rm` aliases out of the `config` node's `commands` array (so the published `help/hop.json` lists `add`/`rm` only at the top level — see [Migration: hidden config aliases](#migration-hidden-config-aliases) above).

Local inspection: run the built binary directly — `hop help-dump | jq .`. There is no dedicated justfile recipe; the former `just help-dump` / `scripts/help-dump.sh` ergonomics wrapper was removed in change `g56l` alongside the shll.ai push-transport teardown (see [build/release-pipeline](../build/release-pipeline.md) § Help reference).
