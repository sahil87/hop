# Plan: Unify Recursive Repo Registration onto `hop add`

**Change**: 260608-w2bj-unify-recursive-add
**Status**: In Progress
**Intake**: `intake.md`

## Requirements

### CLI: `hop add` flag surface

#### R1: `-r`/`--recursive` flag drives a DFS walk
`hop add` SHALL accept a `-r`/`--recursive` boolean flag (default `false`). When set, `runAdd` SHALL discover repos by walking `<dir>` via `scan.Walk` (depth-bounded, symlink-following, (dev,inode)-dedup DFS) instead of classifying just `<dir>` via `scan.ClassifyOne`. All discovered repos SHALL feed the same `buildScanPlan` + write path used by single-dir add.

- **GIVEN** a directory tree containing two convention repos under `~/code`
- **WHEN** the user runs `hop add -r ~/code`
- **THEN** both repos are registered into `hop.yaml`
- **AND** worktrees, bare repos, and no-remote repos are skipped per scan's classification rules

#### R2: `-p`/`--print` flag selects the print (dry-run) sink at both breadths
`hop add` SHALL accept a `-p`/`--print` boolean flag (default `false`). When set, the command SHALL render the merge plan to `cmd.OutOrStdout()` (the bytes a write would produce) and SHALL NOT touch `hop.yaml` (no write, no auto-init). `-p` SHALL be valid both with `-r` (recursive dry-run) and without `-r` (single-dir dry-run); it MUST NOT require `-r`.

- **GIVEN** a single convention repo on disk and an existing `hop.yaml`
- **WHEN** the user runs `hop add -p <repo-dir>`
- **THEN** the rendered plan (header + YAML) is written to stdout
- **AND** `hop.yaml` is left byte-for-byte unchanged
- **GIVEN** a directory tree
- **WHEN** the user runs `hop add -r -p ~/code`
- **THEN** the whole-tree plan is rendered to stdout and nothing is written

#### R3: Write is the default at every breadth
With no `-p` flag, `hop add` SHALL write to `hop.yaml` via `yamled.MergeScan` at every breadth (single-dir and recursive), auto-initing a missing config via `config.EnsureSkeleton` (announcing `created: <path>` to stderr) — matching today's single-dir `add` behavior. The status summary SHALL end in `wrote: <path>`.

- **GIVEN** no `hop.yaml` on a fresh machine
- **WHEN** the user runs `hop add -r ~/code`
- **THEN** the config is auto-created (`created:` announced) and discovered repos are merged in
- **AND** stderr ends with `wrote: <path>`

#### R4: `--depth N` carries over from scan
`hop add` SHALL accept a `--depth N` integer flag (default `3`). It is only meaningful with `-r`. When `N < 1`, the command SHALL emit `hop add: --depth must be >= 1.` to stderr and exit 2.

- **GIVEN** the user passes `--depth 0`
- **WHEN** `hop add -r --depth 0 ~/code` runs
- **THEN** the command exits 2 with the depth-validation message
- **GIVEN** the user passes `--depth 2`
- **WHEN** `hop add -r --depth 2 ~/code` runs
- **THEN** the DFS is bounded to depth 2

#### R5: `-g`/`--group <name>` forces a group with auto-create
`hop add` SHALL accept a `-g`/`--group <name>` string flag (default `""`). When supplied, every discovered repo (single or recursive) SHALL be assigned to `<name>`, overriding both the convention→`default` path and the invented-group path. If `<name>` does not exist in `hop.yaml`, the command SHALL auto-create it as an empty group via `yamled.EnsureGroup` and announce `created group: <name>` to stderr. If `<name>` already exists, repos SHALL be appended with no announcement. `-g` is valid at both breadths and in write mode; in print mode it forces group assignment in the rendered plan without writing.

- **GIVEN** an existing `hop.yaml` with no `vendor` group
- **WHEN** the user runs `hop add -g vendor <repo-dir>`
- **THEN** the `vendor` group is created (`created group: vendor` announced) and the repo is placed in it
- **GIVEN** an existing `hop.yaml` that already has a `work` group
- **WHEN** the user runs `hop add -r -g work ~/clients`
- **THEN** all discovered repos are appended to `work` with no `created group:` announcement

#### R6: Print-mode header and trailer reference the new spelling
In print mode, the rendered header SHALL read:
`# hop config — generated by 'hop add -r -p <user-arg>' on <YYYY-MM-DD> (UTC).` followed by `# Run without --print to merge into <resolved-hop.yaml-path>.`. The stderr summary trailer in print mode SHALL read `Run without --print to merge into <resolved-hop.yaml-path>.` (replacing scan's `--write` phrasing). `<user-arg>` is the user-supplied directory verbatim; `<YYYY-MM-DD>` is `time.Now().UTC()`.

- **GIVEN** a print-mode invocation
- **WHEN** `hop add -r -p ~/code` runs
- **THEN** stdout begins with the `'hop add -r -p ~/code'` header and the `Run without --print` second line
- **AND** stderr ends with `Run without --print to merge into <path>.`

### CLI: command surface reduction

#### R7: `hop config scan` is deleted with no alias
The `hop config scan` cobra subcommand SHALL be removed entirely: `newConfigScanCmd()`, its `runConfigScan` entry point, the `scanLong` help string, and the `scan` wiring in `config.go::newConfigCmd().AddCommand(...)`. No alias SHALL be added — `hop config scan <anything>` SHALL return cobra's `unknown command` error. The shared helpers in `config_scan.go` that `add` depends on (`validateConfigDir`, `buildScanPlan`, `slugifyGroupName`, `scanHeaderComment`, `emitScanSummary`, and plan-resolution helpers) SHALL remain. `internal/scan` is UNTOUCHED.

- **GIVEN** the change is applied
- **WHEN** the user runs `hop config scan ~/code`
- **THEN** cobra returns `unknown command "scan" for "hop config"` and a non-zero exit
- **AND** `hop add -r` and `hop add` still build a plan via the retained shared helpers

#### R8: `config` parent summary drops `scan`
`newConfigCmd()`'s `Short` SHALL change from `"config helpers (init, where, scan, print)"` to `"config helpers (init, where, print)"`.

- **GIVEN** the user runs `hop config --help`
- **WHEN** the help renders
- **THEN** the parent summary reads `config helpers (init, where, print)`

#### R9: Dangling `config scan` references are repointed

Specifically: the `hop config init` post-write tip (`config.go`); the `rootLong` Usage-table row (`root.go`); the `EnsureSkeleton` doc comment listing write-commands (`internal/config/config.go`); the `runAdd`/`addLong` self-references in `config_add.go`. The `Resolve()` not-found message already points at `hop add <dir>` and SHALL be verified unchanged.

- **GIVEN** the change is applied
- **WHEN** grepping `config scan` / `configScan` / `ConfigScan` across `src/` (excluding `internal/scan` package identifiers)
- **THEN** no surviving reference points at the deleted command

- Changing `internal/yamled` — `EnsureGroup`/`MergeScan`/`RenderScan` already exist.
- Migrating `docs/memory/` files — that is a hydrate-stage task, not apply.
- Renaming `config/scan.md` → `config/add-register.md` — hydrate task.
- Adding a `config scan` deprecation notice or hidden alias — explicitly rejected by the user (hard break).

### Design Decisions

1. **Delete `config scan`, no alias**: the command is removed outright; `hop config scan` returns cobra's `unknown command`. — *Why*: user rejected both a hidden alias and a deprecation notice after being shown the back-compat tradeoff twice; cleanest tree. — *Rejected*: hidden alias (drift surface), deprecation notice (clutter).
2. **`-r`/`--recursive`, not `-R`**: conventional Unix spelling. — *Why*: `-R` was a removed flag (the old "run in repo" tool-form precursor, deleted in `gyo0`); reusing it would collide with git/grep history. — *Rejected*: `-R`.
3. **Write-default, `-p` opt-in**: write is the default at every breadth; `-p` is the explicit dry-run. — *Why*: inverts scan's print-by-default papercut (a first run appearing to do nothing); matches today's single-dir `add`. — *Rejected*: print-by-default with `--write` opt-in (the scan behavior being removed).
4. **`-g` auto-creates the group**: a missing `-g <name>` is created via `yamled.EnsureGroup`, not an error. — *Why*: registration-from-disk is a bulk/onboarding operation where forcing a group into existence is the expected intent; consistent with `add` already auto-initing the config; reuses the exact helper `clone` uses (Constitution IV). — *Rejected*: error-on-unknown-group (clone's behavior, which diverges deliberately because clone targets a pre-existing config).
5. **Reuse `buildScanPlan` for both breadths**: the `Found` slice (one element from `ClassifyOne`, many from `Walk`) feeds the same plan-build + write path. — *Why*: `add` and `scan` already share this machinery; the fold is mechanical (Constitution IV, VI).

### Deprecated Requirements

#### `hop config scan <dir>` command
**Reason**: Recursion is folded onto `hop add` as the `-r` flag; print/write is inverted to `-p`-opt-in. The standalone command is redundant and its print-by-default default is an onboarding papercut. Net surface reduction (Constitution VI).
**Migration**: `hop config scan <dir>` → `hop add -r <dir>` (write); `hop config scan <dir> --write` → `hop add -r <dir>` (write); `hop config scan <dir>` (old print default) → `hop add -r -p <dir>` (print). NO alias — the old spelling hard-breaks with `unknown command`.
